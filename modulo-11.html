TEMA 1/3

Herramientas de administración e interacción

Idea principal. Azure proporciona múltiples vías de acceso e interacción con sus servicios, desde interfaces gráficas hasta comandos, scripts y herramientas asistidas por IA.

Herramientas de Administración de AzureMúltiples interfaces sobre una misma API
Azure Portal
Consola web para compilar, administrar y supervisar recursos.
Cloud Shell
Terminal web con autenticación automática.
Azure PowerShell / CLI
Scripting imperativo y comandos multiplataforma.
Copilot in Azure
Asistente IA contextual para acelerar operaciones.

Diferencias clave entre herramientas

Herramienta Plataforma Caso de uso
Azure PortalWeb (Cualquier navegador)Gestión puntual, visualización e inspección gráfica.
Cloud ShellNavegador webLínea de comandos rápida sin instalar software local.
Azure CLIWindows, Linux, macOS, Cloud ShellEntorno basado en comandos Bash.
Azure PowerShellWindows, Linux, macOS, Cloud ShellEntorno basado en Cmdlets e integración con scripts.
Para el examen. Cloud Shell autentica automáticamente con las credenciales con las que iniciaste sesión en el Portal de Azure. No requiere configuración local ni instalación de clientes.

Traducción ASIR

El Portal de Azure es tu Server Manager o la consola RSAT. Cloud Shell es una sesión SSH o PowerShell Remoto precargada en una pestaña del navegador. CLI y PowerShell son los scripts .ps1 o .sh que usas para administrar servidores a gran escala.

TEMA 2/3

Azure Arc

Idea principal. Azure Arc extiende la capa de administración de Azure Resource Manager (ARM) a servidores, clústeres de Kubernetes y bases de datos alojados fuera de Azure (locales o en otras nubes).

Azure Arcvía Azure Resource Manager (ARM)

Azure

  • Recursos nativos de Azure
  • Directivas, supervisión y cumplimiento

On-premises (Local)

  • Servidores Windows / Linux
  • Clústeres Kubernetes
  • SQL Server y Datos

Otras Nubes (Multinube)

  • Instancias de AWS / GCP
  • Servidores y clústeres externos
Para el examen. "Administrar entornos locales, híbridos y multinube de forma unificada desde Azure" es la definición exacta de Azure Arc.

Traducción ASIR

Es como instalar un agente de administración en un servidor físico de tu CPD local o en un VPS de otro proveedor para que aparezca dentro de tu consola central de Active Directory/Azure y puedas aplicar directivas de grupo como si fuera una máquina nativa.

TEMA 3/3

Infraestructura como Código (ARM y Bicep)

Idea principal. IaC (Infraestructura como Código) permite definir la infraestructura deseada en archivos de texto declarativos en lugar de hacer configuraciones manuales. Azure Resource Manager (ARM) ejecuta estas plantillas garantizando un estado coherente y repetible (idempotencia).

Plantillas ARM (JSON) | Bicep (DSL Declarativo)
▼
Azure Resource Manager (ARM)Autenticación + Orquestación
▼
ComputeNetworkingStorage + Data

Plantillas ARM vs Bicep

Característica Plantillas ARM Bicep
Formato / SintaxisJSON (Largo y complejo)DSL (Sencillo, limpio y conciso)
EnfoqueDeclarativoDeclarativo
CompilaciónNativaCompila a JSON de ARM
Para el examen. Las plantillas ARM usan JSON; Bicep es el lenguaje declarativo moderno más conciso y legible. Ambos son idempotentes (puedes ejecutarlos N veces y el resultado siempre será exactamente el mismo).

Traducción ASIR

Es el equivalente a los archivos de respuesta XML o scripts de Despliegue Desatendido (Unattended Installation / DSC) en Windows Server: defines qué quieres tener instalado y el sistema se encarga de crearlo en el orden correcto.

Qué cae en el examen

❌ Error típico ✅ Concepto correcto 🔑 Palabra clave
Creer que Azure Arc es solo para recursos dentro de la nube de Azure. Azure Arc proyecta recursos fuera de Azure (locales/multinube) dentro de ARM. Híbrido, On-premises, Multinube
Pensar que Bicep reemplaza la arquitectura de ARM. Bicep es una capa sintáctica simplificada sobre ARM. Compila a JSON. Declarativo, IaC, Bicep

Preguntas de Learn

1. ¿Qué servicio le ayuda a administrar los entornos de Azure, locales y multinube?

✅ Respuesta: Azure Arc.

Razón: Azure Arc extiende ARM hacia infraestructuras situadas fuera del centro de datos nativo de Azure.

2. ¿Qué dos componentes podría usar para implementar una implementación de "infraestructura como código"?

✅ Respuesta: Plantillas de Bicep y ARM.

Razón: Ambos son lenguajes declarativos nativos procesados por Azure Resource Manager.

Repaso final (Flashcards)

  • ARM: Punto de entrada único que procesa, autentica y orquesta todas las peticiones en Azure.
  • Cloud Shell: Consola web autenticada que no requiere software instalado localmente.
  • Azure Arc: Puente para gobernar servidores locales y de otras nubes.
  • Bicep: Sintaxis declarativa simplificada para Infraestructura como Código.
  • Copilot: Asistente operativo de IA (las decisiones finales siempre son humanas).
