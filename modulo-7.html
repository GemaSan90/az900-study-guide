TEMA 1/5

Cuenta de almacenamiento

Idea principal. La cuenta de almacenamiento es el contenedor principal donde viven los servicios de almacenamiento de Azure: Blob, Files, Queues y Tables. En ella eliges la redundancia y es el punto de acceso a tus datos.

Cuenta de almacenamiento

BlobObjetos
FilesArchivos
QueuesMensajes
TablesNoSQL

Los discos (Disks) son un servicio de almacenamiento, pero van asociados a las máquinas virtuales.

Para el examen

Regla del nombreDetalle
ÚnicoEn todo Azure, no solo en tu suscripción
LongitudEntre 3 y 24 caracteres
CaracteresSolo minúsculas y números

Ejemplo: empresaalmacen01

Traducción ASIR

Es el sistema principal que agrupa discos, carpetas y servicios, como un servidor de almacenamiento con todas sus funciones.

TEMA 2/5

Los cinco servicios de almacenamiento

Idea principal. Cada servicio guarda un tipo de dato distinto. En el examen casi siempre se trata de relacionar el escenario con la palabra clave: objetos, archivos compartidos, mensajes, NoSQL o discos de máquina virtual.

Blob Storage

Almacenamiento de objetos para datos no estructurados: imágenes, vídeos y copias de seguridad.

ASIR

Repositorio masivo de ficheros accesibles por web.

Examen
  • Datos binarios.
  • Incluye Data Lake Storage Gen2.
  • Muy usado para Big Data.

Ejemplo: copias de seguridad.

Azure Files

Recursos compartidos de archivos gestionados por Azure, con acceso desde Windows y Linux.

ASIR

NAS o servidor de archivos en la nube.

Examen
  • Protocolos SMB y NFS.
  • Se sincroniza con Azure File Sync.

Ejemplo: carpeta compartida de un departamento.

Queue Storage

Cola de mensajes para procesamiento asíncrono entre aplicaciones.

ASIR

Cola de tareas entre aplicaciones.

Examen

  • Procesamiento asíncrono y diferido.

Ejemplo: un pedido pendiente de procesar.

Azure Disks

Discos administrados para máquinas virtuales, con almacenamiento por bloques y alto rendimiento.

ASIR

Examen

Ejemplo: el disco del sistema operativo.

Base de datos NoSQL simple y escalable para datos estructurados no relacionales.

TEMA 3/5

Redundancia

Idea principal. Azure guarda varias copias de tus datos. La redundancia que elijas decide hasta qué fallo sobreviven: un equipo, un centro de datos, una zona o una región entera.

Menos protección y más baratoMás protección
LRS3 copias en un centro de datos
ZRS3 zonas de la misma región
GRSOtra región
RA-GRSOtra región + lectura
GZRSZonas + otra región
RA-GZRSZonas + región + lectura

Comparativa

RedundanciaZonasSegunda regiónLectura secundaria
LRSNoNoNo
ZRSSíNoNo
GRSNoSíNo
RA-GRSNoSíSí
GZRSSíSíNo
RA-GZRS AmpliaciónSíSíSí

«Zonas» significa que sobrevive al fallo de un centro de datos o zona de la región principal. La tabla de Copilot no traía RA-GZRS y lo he añadido.

Qué es cada una

LRS

Tres copias en un mismo centro de datos. Es lo más barato. Protege frente a fallos de hardware (disco, servidor, rack), no frente a un incendio o una caída del centro ni de la región.

ASIR: réplica local dentro del CPD.

ZRS

Replica entre tres zonas de disponibilidad de la misma región. Aguanta la caída de una zona, pero no la de una región.

ASIR: equipos repartidos en varios edificios.

GRS y RA-GRS

Copia asíncrona a otra región para recuperarte de un desastre. GRS no permite leer en la secundaria. RA-GRS sí: RA es Read Access.

ASIR: copia remota en otro CPD.

GZRS y RA-GZRS

Combinan ZRS en la región principal y copia a otra región. Protegen frente al fallo de una zona y al de una región.

ASIR: zonas y región a la vez.

Para el examen. ZRS + GRS = GZRS. Cuando el enunciado pide la máxima resiliencia o la mayor durabilidad, la respuesta es GZRS. Si además pide leer cuando la principal cae, añade el prefijo RA.

Matices de Learn (los he añadido): Azure Files no admite RA-GRS ni RA-GZRS, y los discos administrados solo usan LRS o ZRS.

TEMA 4/5

Niveles de acceso de Blob

Idea principal. Los niveles te dejan pagar menos según lo a menudo que uses un dato. Cuanto más frío es el nivel, más barato es guardarlo y más caro es acceder a él.

Guardar más caro, acceso más baratoGuardar más barato, acceso más caro
HotAcceso frecuente
CoolAcceso poco frecuente
ColdAcceso raro
ArchiveAcceso mínimo
NivelFrecuencia de accesoPermanencia mínima recomendada
HotAltaNinguna
CoolMedia30 días
ColdBaja90 días
ArchiveMínima180 días
Archive es distinto. Es un nivel sin conexión (offline): para leer un dato hay que rehidratarlo antes a un nivel en línea y tarda horas. Los demás niveles responden en milisegundos.

La columna de permanencia mínima la he añadido desde Learn. En el examen lo que importa es la frecuencia de acceso.

TEMA 5/5

Migración y movimiento de datos

Idea principal. Para llevar datos a Azure hay dos preguntas: ¿qué quiero mover?, ¿cuánto y con qué red? Azure Migrate evalúa y migra servidores, Data Box lleva los datos físicamente, y AzCopy, Storage Explorer y Azure File Sync mueven archivos por la red.

Azure Migrate

Evalúa y migra servidores, bases de datos y aplicaciones a Azure.

ASIR

Inventario y migración de servidores.

Examen
  • Descubrimiento, evaluación y migración.
  • Migración por red (la opuesta a Data Box).

Azure Data Box

Dispositivo físico que Microsoft te envía: copias los datos, lo devuelves y se suben a Azure.

ASIR

Disco externo gigante enviado por Microsoft.

Examen
  • Muchos TB de datos.
  • Red lenta, cara o insuficiente.

AzCopy

Herramienta de línea de comandos para copiar y sincronizar datos con cuentas de almacenamiento.

ASIR

Parecida a rsync o robocopy.

Examen
  • Línea de comandos, ideal para automatizar.
  • La sincronización es en un solo sentido.

Storage Explorer Ampliación

Aplicación gráfica para ver y gestionar tus cuentas de almacenamiento.

ASIR

El explorador de archivos de Azure Storage.

Examen
  • Interfaz gráfica (GUI).
  • Para transferencias puntuales, sin automatizar.

Azure File Sync

Sincroniza servidores Windows con Azure Files y deja una caché local de los archivos que más usas.

ASIR

Servidor híbrido local y nube.

Examen
  • Sincronización automática en ambos sentidos.
  • Solución híbrida.

Preguntas de Learn

Intenta responder antes de abrirlas.

¿Qué herramienta mantiene actualizados los archivos entre Windows Server y Azure?

Azure File Sync.

Por qué. Sincroniza automáticamente archivos entre el entorno local y Azure Files.

Trampa. AzCopy copia. Storage Explorer administra.

¿Qué redundancia proporciona la mayor durabilidad?

GZRS.

Por qué. Combina protección por zonas y por regiones.

Trampa. ZRS no protege frente a una región completa.

¿Qué servicio admite análisis de macrodatos y almacenamiento binario?

Blob Storage.

Por qué. Está pensado para datos no estructurados y Data Lake.

Trampa. Azure Files comparte archivos, no objetos.

Repaso final

Frases de examen

  • Blob Storage almacena datos no estructurados.
  • Azure Files usa SMB y NFS.
  • LRS replica los datos en un único centro de datos.
  • ZRS replica entre zonas de disponibilidad.
  • GRS replica los datos en otra región.
  • RA-GRS permite lectura en la región secundaria.
  • GZRS combina redundancia zonal y geográfica.
  • Azure Migrate es una solución de migración por red.
  • Data Box se usa cuando la red no es suficiente.
  • Azure File Sync sincroniza servidores locales con Azure Files.
