TEMA 1/9

Tipos de proceso en Azure

Idea principal. Proceso (compute) es el servicio que ejecuta tu código o tus aplicaciones. Azure ofrece varias formas de hacerlo. Todas se ordenan en una misma escala: cuanto más control quieres, más administración te toca, y cuanto más administra Azure, menos controlas.

La escala de control

Máquinas virtualesIaaS
AKSOrquestación de contenedores
Container Instances y Container AppsContenedores gestionados
App ServicePaaS web
Azure FunctionsSin servidor
← Más control y más administraciónMenos administración →

Es una guía de estudio, no una clasificación oficial: Learn dibuja el mismo espectro entre máquinas virtuales, contenedores y App Service.

Los tres tipos que compara la guía

TipoQué ejecutasQué administras túServicio típico
Máquina virtualUn servidor completoSistema operativo, parches y softwareAzure Virtual Machines
ContenedorUna aplicación aislada con sus dependenciasLa imagen del contenedor. No administras el sistema operativoACI, Container Apps, AKS
FunciónUn trozo de código que responde a un eventoSolo el códigoAzure Functions

Cuál elegir según la necesidad

Si la necesidad es…Piensa en
Control total del sistema operativo o mover un servidor tal cualAzure Virtual Machines
Publicar una aplicación web o una API sin administrar servidoresAzure App Service
Ejecutar código solo cuando ocurre un eventoAzure Functions
Ejecutar un contenedor simple, sin orquestaciónAzure Container Instances
Aplicaciones o microservicios en contenedores con escalado integradoAzure Container Apps
Gestionar una flota grande de contenedoresAzure Kubernetes Service

Traducción ASIR

Es como decidir cuánto de la cocina montas tú. Con una máquina virtual instalas y administras el servidor. Con contenedores empaquetas solo la aplicación. Con App Service solo subes la aplicación web. Con Functions solo escribes el código. Cuanto más abajo en la lista, menos tareas de sistemas te quedan.

TEMA 2/9

Azure Virtual Machines

Idea principal. Azure Virtual Machines permite ejecutar servidores Windows o Linux en la nube con control total sobre el sistema operativo y las aplicaciones. Es IaaS: Microsoft pone el hardware y tú sigues encargándote de los parches, las actualizaciones y la configuración dentro de la máquina.

Una máquina virtual es un servidor tuyo alojado en el centro de datos de Microsoft.

Usuario▼Azure VM▼
Windows o LinuxAplicacionesDatos

Esquema de los apuntes de Copilot, rehecho en español.

Cuándo usarla

CasoQué significa
Migración lift-and-shiftTrasladar un servidor existente con mínimos cambios en la aplicación.
Aplicaciones heredadasSoftware que necesita un sistema operativo y una configuración concretos.
Acceso administrativoCuando necesitas total control del sistema operativo o instalar software propio.
Pruebas y desarrolloCreas configuraciones distintas con rapidez y las quitas al terminar.
Extensión del centro de datosAmplías tu red local a Azure y alojas cargas en una red virtual conectada.
Recuperación ante desastresMantienes capacidad de reserva en Azure por si falla el sitio principal.

AmpliaciónExtensión del centro de datos y recuperación ante desastres vienen del módulo de Learn. Los apuntes de Copilot listaban los otros cuatro.

Recursos que necesita una máquina virtual

La guía pide describir qué hace falta para crear una máquina virtual. Al aprovisionarla eliges tres cosas.

Tamaño

Para qué se usa, cuántos núcleos de procesador y cuánta memoria RAM.

Discos de almacenamiento

Discos duros o unidades de estado sólido. Afectan a la capacidad y al rendimiento.

Red

Red virtual, dirección IP pública y configuración de puertos.

La máquina virtual se despliega a partir de una imagen: una plantilla que ya incluye un sistema operativo y herramientas, como componentes de alojamiento web.

Familias de máquinas virtuales

Azure agrupa los tamaños en familias según la carga de trabajo. Se elige primero la familia que encaja con el comportamiento y después el tamaño.

SerieUsoEjemplo
BBajo coste, con picos de CPU ocasionalesPruebas y desarrollo
DUso generalServidores web y de aplicaciones pequeños o medianos
EOptimizada para memoriaBases de datos en memoria, análisis
FOptimizada para CPUCapas de aplicación que usan mucho procesador
MMucha memoriaGrandes bases de datos empresariales
LOptimizada para almacenamientoProcesamiento de datos con alto rendimiento de disco
NCon GPUIA y gráficos

AmpliaciónEl nombre de un tamaño también informa. En Standard_D2s_v5: D es la familia, 2 los vCPU, s indica que admite discos Premium SSD y v5 es la generación de hardware.

Traducción ASIR

Es una máquina virtual de VMware, Hyper-V o Proxmox, pero el host físico no está en tu empresa. Si sabes instalar Windows Server o Ubuntu Server, ya sabes administrar una máquina virtual de Azure. Lo que cambia es dónde está el hardware.

Frases de examen

Necesita control total sobre el sistema operativo.

Quiere ejecutar software personalizado.

Va a migrar un servidor existente sin rediseñarlo.

Si aparece alguna de estas frases, la respuesta es una máquina virtual (IaaS).

Errores frecuentes

ErrorLo que pasa en realidad
Pensar que Azure parchea el sistema operativo de la máquina virtualEn IaaS los parches y la configuración interna son tuyos.
Elegir una máquina virtual para una web sencillaSi no necesitas controlar el sistema operativo, App Service da menos trabajo.

Preguntas de comprensión

¿Quién mantiene el sistema operativo de una máquina virtual de Azure?

El cliente.

Azure mantiene el hardware y el centro de datos. Dentro de la máquina, el sistema operativo, los parches y el software son tuyos.

¿Qué familia elegirías para una base de datos que guarda muchos datos en memoria?

La serie E, optimizada para memoria.

Si la base de datos es muy grande, la serie M ofrece aún más memoria.

TEMA 3/9

Escalabilidad y disponibilidad de las máquinas virtuales

Idea principal. Puedes ejecutar una máquina virtual suelta para pruebas, o agruparlas para ganar disponibilidad, escalabilidad y redundancia. Azure lo hace con dos funciones: los Scale Sets y los conjuntos de disponibilidad.

Virtual Machine Scale Sets

Permiten crear y administrar un grupo de máquinas virtuales idénticas con balanceo de carga. Pueden escalar hacia fuera o hacia dentro automáticamente según la demanda o según un horario, y se integran con el balanceador de carga para repartir el tráfico.

Usuarios▼Balanceador de carga▼
VM 1VM 2VM 3

Sin Scale Sets tendrías que mantener la configuración de cada máquina, vigilar el uso y ajustar el número de instancias a mano.

Conjuntos de disponibilidad

Distribuyen las máquinas virtuales en distintos dominios de actualización y de error. Así reduces la probabilidad de que un mantenimiento o un fallo de hardware afecte a todas a la vez. Mejoran la resiliencia dentro de una región.

Dominio de actualización

Máquinas que pueden reiniciarse juntas durante un mantenimiento planificado.

Dominio de error

Máquinas que comparten un posible punto de fallo de energía o de red.

Dominio de error 1 (un rack)

VM 1 actualización 1
VM 3 actualización 2

Dominio de error 2 (otro rack)

VM 2 actualización 1
VM 4 actualización 2

Ejemplo ilustrativo. Si falla un rack, quedan dos máquinas en pie. Si se reinicia la actualización 1, siguen funcionando las de la actualización 2.

Dato de Learn. Los conjuntos de disponibilidad no añaden coste: pagas por las máquinas. En las regiones con zonas de disponibilidad, un diseño basado en zonas suele preferirse porque aísla fallos más amplios (Módulo 4).

Scale Sets frente a conjuntos de disponibilidad

CaracterísticaScale SetsConjuntos de disponibilidad
ObjetivoEscalar según la demandaSeguir funcionando ante mantenimientos y fallos
Cómo lo lograCrea o quita instancias idénticasReparte las máquinas en dominios de actualización y de error
Palabra claveEscalar, balanceo de cargaAlta disponibilidad, dominios

Traducción ASIR

Un Scale Set es como un clúster de servidores web iguales detrás de un balanceador, que crece o encoge solo. Un conjunto de disponibilidad es colocar tus servidores en racks y circuitos eléctricos distintos, y programar las actualizaciones por turnos para que no caigan todos a la vez.

Frases de examen

Escalar automáticamente un grupo de máquinas virtuales idénticas.

Escalonar las actualizaciones entre máquinas según el dominio de actualización y de error.

Errores frecuentes

ErrorLo que pasa en realidad
Confundir Scale Sets con conjuntos de disponibilidadUno escala según la demanda. El otro evita que una incidencia afecte a todas las máquinas.
Creer que un conjunto de disponibilidad escala soloNo crea ni quita máquinas. Solo las distribuye.

Preguntas de comprensión

¿Qué función de las máquinas virtuales escalona las actualizaciones según el dominio de actualización y el de error?

Los conjuntos de disponibilidad.

Los Scale Sets escalan, pero no organizan dominios de actualización y de error. «Update sets» no existe como función.

Una tienda en línea recibe picos de tráfico en rebajas. ¿Qué usarías?

Virtual Machine Scale Sets.

Crean más instancias idénticas cuando sube la demanda y las quitan cuando baja, con el tráfico repartido por el balanceador.

TEMA 4/9

Azure Virtual Desktop

Idea principal. Azure Virtual Desktop es un servicio de virtualización de escritorios y aplicaciones en Azure. Permite acceder de forma segura a escritorios y aplicaciones Windows desde muchos tipos de dispositivos y ubicaciones, porque los escritorios viven en la nube y no en los equipos locales.

Usuario→Microsoft Entra ID→Grupo de hosts en Azure→Escritorio o aplicación

Ventajas

  • Acceso desde cualquier lugar.
  • Administración centralizada de escritorios y aplicaciones.
  • Integración con Microsoft Entra ID para identidad y accesos.
  • Menor dependencia de los equipos locales: los datos pueden quedarse en Azure y no en el dispositivo.
  • Admite sesiones únicas y multisesión de Windows, según el usuario y la carga.

Cuándo usarlo

Cuando un equipo necesita escritorios y aplicaciones centralizados para usuarios distribuidos, contratistas o trabajadores híbridos. Por ejemplo, un equipo de soporte con escritorios idénticos en la nube, con las mismas herramientas y políticas de seguridad en cada turno. Suele ser más fácil de operar que montar entornos de máquinas virtuales separados para cada grupo.

Traducción ASIR

Equivale a un entorno Remote Desktop Services (Terminal Server) moderno, alojado en la nube y gestionado con Microsoft Entra ID en lugar de con tu propio Active Directory local.

Errores frecuentes

ErrorLo que pasa en realidad
Confundirlo con una máquina virtual normalUna máquina virtual es un servidor. Virtual Desktop entrega escritorios y aplicaciones a muchos usuarios con administración central.

Preguntas de comprensión

¿Qué ventaja de seguridad ofrece Azure Virtual Desktop?

Reduce la exposición de datos en los equipos locales.

Las aplicaciones y los datos pueden permanecer en sesiones alojadas en Azure, y el acceso se controla con Microsoft Entra ID.

TEMA 5/9

Contenedores: ACI, Container Apps y AKS

Idea principal. Un contenedor ejecuta una aplicación aislada compartiendo el sistema operativo del host. Se puede ejecutar varios en una misma máquina, física o virtual. Son ligeros y están pensados para crearse, escalarse y detenerse de forma dinámica. Docker es uno de los motores de contenedores más populares y Azure lo admite.

Microservicios: el caso típico

Con contenedores puedes dividir una solución en piezas independientes, por ejemplo un contenedor para el front-end, otro para el back-end y otro para el almacenamiento. Si el back-end llega a su límite, escalas solo esa pieza. También puedes cambiar el almacenamiento o modificar el front-end sin afectar al resto.

Traducción ASIR

Un contenedor es una aplicación empaquetada con lo que necesita, como una imagen ligera que arranca en segundos. AKS equivale a administrar una granja de servidores que reparte y escala aplicaciones automáticamente, algo parecido a lo que Docker Swarm hacía a pequeña escala.

Frases de examen

Ejecutar un contenedor de forma rápida y sencilla, sin orquestación.

Aplicación basada en microservicios con escalado automático.

Orquestar y gestionar el ciclo de vida de muchos contenedores.

Errores frecuentes

ErrorLo que pasa en realidad
Docker y Kubernetes son lo mismoDocker ejecuta contenedores. Kubernetes los administra y orquesta.
Un contenedor es una máquina virtual pequeñaNo tiene sistema operativo propio: usa el del host.
Usar AKS para ejecutar un solo contenedor sencilloPara eso basta ACI. AKS compensa cuando hay que orquestar una flota.

Preguntas de comprensión

¿Por qué los contenedores arrancan más rápido que las máquinas virtuales?

Porque no arrancan un sistema operativo completo.

Comparten el del host y empaquetan solo la aplicación y sus dependencias, así que consumen menos y se inician enseguida.

Una aplicación en contenedores necesita escalar sola según la demanda, sin gestionar Kubernetes. ¿Qué elegirías?

Azure Container Apps.

Incluye balanceo de carga y escalado integrados y elimina la administración de los contenedores. AKS daría más control, pero exige más administración.

TEMA 6/9

Azure Functions

Idea principal. Azure Functions es un servicio de proceso sin servidor y basado en eventos. No hay que mantener máquinas virtuales ni contenedores: un evento activa la función y, al terminar, Azure libera los recursos. Solo pagas por el tiempo de CPU que usa tu código mientras se ejecuta.

Evento→Azure Function→Resultado

Triggers frecuentes

  • Una petición HTTP, por ejemplo una llamada REST.
  • Un temporizador.
  • Un mensaje en una cola o de otro servicio de Azure.

Cuándo encaja

  • Cuando solo te preocupa el código y no la plataforma ni la infraestructura.
  • Cuando el trabajo termina rápido, en segundos o menos.
  • Cuando la demanda es variable: escala automáticamente.

Detalles que conviene saber

ConceptoQué significa
Sin estado (por defecto)La función se comporta como si se reiniciara cada vez que responde a un evento.
Con estado: Durable FunctionsEl motor pasa un contexto para recordar la actividad previa.
FacturaciónPor el tiempo de CPU usado mientras la función se ejecuta.
FlexibilidadSi cambian las necesidades, puedes desplegar el proyecto fuera del modelo sin servidor para controlar el escalado o aislarlo.

Traducción ASIR

Es como un script que se ejecuta solo cuando salta un cron o un webhook, pero sin servidor que mantener. «Sin servidor» no significa que no haya servidores: los gestiona Azure y tú no los ves.

Frases de examen

Ejecutar código en respuesta a un evento.

Sin administrar máquinas virtuales ni contenedores.

Pagar solo cuando el código se ejecuta.

Errores frecuentes

ErrorLo que pasa en realidad
Azure Functions es una máquina virtualEs un servicio sin servidor.
Sin servidor significa que no existen servidoresExisten, pero Azure los administra por ti.

Preguntas de comprensión

¿Qué opción de proceso es sin servidor y se activa por eventos?

Azure Functions.

Azure Virtual Machines es IaaS y exige administrar la máquina. Container Instances ejecuta contenedores sin servidores que administrar, pero no es un modelo basado en eventos.

¿Por qué Functions puede salir más barato que una máquina virtual para tareas esporádicas?

Porque no hay recursos encendidos esperando.

Un evento despierta la función, se ejecuta y los recursos se liberan. Pagas el tiempo de CPU usado, no una máquina encendida todo el día.

TEMA 7/9

Azure App Service y opciones de hospedaje

Idea principal. App Service es un servicio PaaS para hospedar aplicaciones web, APIs y backends móviles sin administrar los servidores. Azure mantiene el entorno funcionando y tú te centras en construir y mantener la aplicación.

Qué aloja

TipoQué es
Aplicaciones webSitios con ASP.NET, Java, Ruby, Node.js, PHP o Python, en Windows o en Linux.
Aplicaciones de APIAPIs REST con el lenguaje y el marco que prefieras.
WebJobsProgramas o scripts en segundo plano, programados o activados por un trigger.
Aplicaciones móvilesBackend para aplicaciones iOS y Android.

Lo que ya trae

  • Despliegue y administración integrados, con despliegue continuo desde GitHub, Azure DevOps o cualquier repositorio Git.
  • Puntos de conexión que se pueden proteger.
  • Escalado rápido ante picos de tráfico.
  • Balanceo de carga integrado, con alta disponibilidad.

Las tres formas de hospedar una aplicación

Máquinas virtualesMáximo control
ContenedoresAíslan y gestionan cada pieza
App ServiceMenos esfuerzo operativo
OpciónElígela cuando…
Máquina virtualNecesitas controlar el entorno y configurarlo exactamente como quieres. Es lo más familiar si vienes de sistemas.
ContenedoresQuieres aislar y gestionar por separado cada parte de la solución.
App ServiceEs una aplicación web, una API o un backend móvil y no quieres administrar infraestructura.

Traducción ASIR

Equivale a publicar una aplicación en IIS o en Apache sin tener que administrar el servidor ni el sistema operativo. Subes la aplicación y la plataforma pone el servidor web, los parches y el balanceo.

Frases de examen

Hospedar una aplicación web o una API sin administrar la infraestructura.

Despliegue continuo desde GitHub y escalado automático.

Errores frecuentes

ErrorLo que pasa en realidad
Pensar que se administra el sistema operativo de App ServiceLo administra Azure. Es PaaS.
Creer que solo hospeda páginas webTambién aloja APIs, tareas en segundo plano (WebJobs) y backends móviles.

Preguntas de comprensión

¿Qué servicio hospeda aplicaciones web y APIs sin administrar la infraestructura?

Azure App Service.

Azure Virtual Machines exige administrar el sistema operativo, y ExpressRoute es un servicio de conexión de red, no de hospedaje.

¿Cuándo preferirías una máquina virtual a App Service para alojar una web?

Cuando necesites control sobre el sistema operativo o software especial.

Si la aplicación depende de una configuración concreta del servidor, App Service no te dejará tocar esa capa. Si no, App Service da menos trabajo.

TEMA 8/9

Ampliación: inteligencia artificial e IoT

Idea principal. Tus apuntes incluían servicios de IA y de IoT. No aparecen entre las habilidades de proceso de la guía de estudio del AZ-900, salvo una pregunta de la evaluación del módulo de Learn sobre servicios de IA. Lo dejo como ampliación para entender el mapa de servicios.

Azure AI services

Servicios de IA preentrenados que se consumen por API, sin entrenar un modelo propio. Casos de uso:

  • Reconocimiento de imágenes y vídeo.
  • Procesamiento de lenguaje.
  • Transcripción de voz.
  • Análisis de documentos.

Azure OpenAI es el servicio de IA generativa para chat, automatización y generación de contenido.

Cambio de nombre. Microsoft ha renombrado Azure AI services como Foundry Tools, y Azure OpenAI se ofrece dentro de Microsoft Foundry. La evaluación de Learn sigue diciendo «Azure AI services», así que en el examen puede aparecer con cualquiera de los dos nombres.

Azure Machine Learning

Plataforma para crear, entrenar y administrar modelos de Machine Learning personalizados.

ServicioModelosCuándo
Azure AI servicesYa entrenadosUn API cubre tu caso: visión, voz, lenguaje o documentos.
Azure Machine LearningPropios, los creas y entrenas túNecesitas un modelo a medida con tus datos.

Azure IoT

Servicios para conectar y administrar dispositivos físicos.

ServicioObjetivo

Traducción ASIR

IoT Hub es el servidor central que recibe la telemetría de todos los sensores. IoT Edge es un pequeño servidor en la propia fábrica que filtra y procesa datos antes de enviarlos, igual que un proxy o una caché local reducen el tráfico hacia fuera.

Preguntas de comprensión

¿Qué categoría de servicios ofrece APIs de visión, voz y lenguaje sin entrenar un modelo propio?

Azure AI services.

Es la pregunta 4 de la evaluación de Learn. Las otras opciones, Virtual Machines y Virtual Networks, no son servicios de IA.

Comprobación de conocimientos de Learn

La evaluación del módulo tiene cuatro preguntas sobre proceso, hospedaje e IA. Las que tratan de redes se verán en el siguiente manual. Intenta responder antes de abrirlas.

1. ¿Qué función de las máquinas virtuales escalona las actualizaciones según su dominio de actualización y de error?

Conjuntos de disponibilidad.

Por qué. Agrupan las máquinas en dominios de actualización (se reinician juntas en un mantenimiento) y de error (comparten energía o red), y así evitan que todas caigan a la vez.

Por qué no Scale Sets. Sirven para crear y escalar grupos de máquinas idénticas, no para repartir dominios.

Por qué no «update sets». No es una función de Azure.

2. ¿Qué opción de proceso es basada en eventos y sin servidor, para ejecutar código sin administrar máquinas virtuales?

Azure Functions.

Por qué. Un evento activa el código y los recursos se liberan al terminar. Pagas solo el tiempo de CPU.

Por qué no Virtual Machines. Es IaaS: administras el servidor.

Por qué no Container Instances. Ejecuta contenedores sin servidores que administrar, pero es para contenedores, no para código activado por eventos.

3. ¿Qué servicio permite hospedar aplicaciones web y APIs sin administrar la infraestructura?

Azure App Service.

Por qué. Es un servicio PaaS HTTP para aplicaciones web, APIs y backends móviles.

Por qué no Virtual Machines. Tendrías que administrar el sistema operativo.

Por qué no ExpressRoute. Es un servicio de conectividad de red, no de hospedaje.

4. ¿Qué categoría de servicios de Azure ofrece APIs preconstruidas de visión, voz y lenguaje sin entrenar tu propio modelo?

Azure AI services.

Por qué. Son servicios preentrenados que se consumen por API.

Por qué no Virtual Machines ni Virtual Networks. Son proceso y redes, no IA.

Preguntas de repaso

¿Qué es una máquina virtual de Azure?

Un servidor Windows o Linux en la nube con control total del sistema operativo. Es IaaS.

¿Qué familia de máquinas virtuales es para GPU e IA?

La serie N.

¿Qué hacen los Scale Sets?

Crean y escalan grupos de máquinas virtuales idénticas con balanceo de carga.

¿Qué evitan los conjuntos de disponibilidad?

Que un mantenimiento o un fallo de hardware afecte a todas las máquinas a la vez.

¿Qué es un dominio de error?

Un grupo de máquinas que comparten un posible punto de fallo de energía o de red.

¿Para qué sirve Azure Virtual Desktop?

Para entregar escritorios y aplicaciones Windows alojados en Azure a usuarios en cualquier lugar.

¿Qué diferencia hay entre una máquina virtual y un contenedor?

La máquina virtual tiene su sistema operativo. El contenedor usa el del host, por lo que arranca más rápido y consume menos.

¿Qué servicio de contenedores es el más sencillo?

Azure Container Instances.

¿Qué servicio de contenedores es el recomendable para microservicios con escalado integrado?

Azure Container Apps.

¿Qué es AKS?

Un servicio de orquestación de contenedores basado en Kubernetes.

¿Qué desencadena una función?

Un evento: una petición HTTP, un temporizador o un mensaje en una cola.

¿Qué cuatro tipos de aplicación aloja App Service?

Aplicaciones web, aplicaciones de API, WebJobs y aplicaciones móviles.

¿Qué diferencia hay entre IoT Hub e IoT Edge?

IoT Hub es el centro de mensajes en la nube. IoT Edge ejecuta lógica en el dispositivo, cerca de los sensores.

Escenarios para practicar

Ejercicios propios para entrenar la elección de servicio. No son preguntas de Microsoft.

Una empresa tiene un servidor con una aplicación antigua que exige una versión concreta de Windows Server y quiere moverlo a Azure sin cambios.

Azure Virtual Machines.

Necesita control del sistema operativo y una migración lift-and-shift.

Una web de tickets recibe diez veces más visitas el día que salen a la venta.

Scale Sets o App Service con escalado automático.

Si la web corre en máquinas virtuales, Scale Sets. Si es una aplicación web sin necesidad de controlar el servidor, App Service.

Quieres que cada vez que se suba una foto a una carpeta se genere una miniatura, sin tener un servidor encendido.

Azure Functions.

Es código corto activado por un evento.

Un equipo de desarrollo quiere ejecutar un contenedor de pruebas durante una tarde y borrarlo después, sin montar nada.

Azure Container Instances.

Es la forma más rápida y sencilla de ejecutar un contenedor sin orquestación.

Una empresa tiene cientos de contenedores y necesita repartirlos y escalarlos con control avanzado.

Azure Kubernetes Service.

Es orquestación de una flota de contenedores.

Una consultora quiere dar a sus contratistas el mismo escritorio Windows con las mismas herramientas, desde cualquier equipo.

Azure Virtual Desktop.

Escritorios centralizados en Azure, con acceso controlado por Microsoft Entra ID.
