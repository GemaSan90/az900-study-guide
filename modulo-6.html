TEMA 2/10

Subredes (subnets)

Idea principal. Las subredes dividen una red virtual en segmentos lógicos independientes. Al crear la VNet defines un espacio de direcciones IP y asignas una parte a cada subred con nombre. Facilitan la organización, la seguridad y la administración.

Si la VNet es el edificio, las subredes son las plantas o los departamentos.

Cuándo usarlas

  • Separar las bases de datos.
  • Aislar los servidores web.
  • Segmentar la seguridad.
  • Aplicar reglas específicas a cada grupo de recursos.

Ejemplo: una tienda en línea

VNet de la tienda

Frontend

La web que ve el cliente

Backend

Pedidos y pagos

Base de datos

Catálogo y clientes

Traducción ASIR

Equivale a las VLAN de una red empresarial: una misma red física dividida en segmentos lógicos con reglas distintas. Es una analogía didáctica. En Azure el aislamiento lo marcan las reglas que apliques a cada subred.

Errores frecuentes

ErrorLo que pasa en realidad
Confundir segmentación con disponibilidadLas subredes segmentan la red. Las zonas y los conjuntos de disponibilidad evitan caídas.

Preguntas de comprensión

¿Qué función de red divide una red virtual en segmentos lógicos más pequeños?

Las subredes.

Es la pregunta 1 de la evaluación de Learn. Los conjuntos de disponibilidad son de máquinas virtuales y los bloqueos de recursos protegen contra borrados.

TEMA 3/10

Puntos de conexión públicos y privados

Idea principal. Azure admite dos tipos de punto de conexión para que los recursos se comuniquen. Un punto de conexión público tiene IP pública y se puede alcanzar desde cualquier lugar del mundo. Uno privado vive dentro de una red virtual y tiene una IP privada de su espacio de direcciones.

Punto de conexión público

IP pública. Accesible desde cualquier lugar. Es el caso de una web que quieres que vea todo el mundo.

Punto de conexión privado

IP privada dentro de la VNet. Solo se llega desde la red virtual o redes conectadas a ella.

AmpliaciónLos apuntes de Copilot no incluían este tema. Está en la guía de estudio y en la unidad de redes virtuales de Learn.

Puntos de conexión de servicio

Sirven para enlazar una red virtual con otros tipos de recurso de Azure, como bases de datos Azure SQL o cuentas de almacenamiento. Mejoran la seguridad y dan un enrutamiento óptimo entre los recursos.

Traducción ASIR

Un punto de conexión privado es como un servidor con dirección solo interna, sin puerto expuesto a Internet. El público es el servidor en la DMZ con IP pública.

Errores frecuentes

ErrorLo que pasa en realidad
Pensar que todo recurso de Azure es privado por defectoUn punto de conexión público es accesible desde Internet salvo que lo restrinjas.

Preguntas de comprensión

¿Qué tipo de punto de conexión tiene una IP del espacio de direcciones de la red virtual?

El privado.

El público tiene una IP pública y se alcanza desde cualquier lugar.

TEMA 4/10

Filtrar y enrutar el tráfico: NSG, rutas y BGP

Idea principal. Dentro de una red virtual puedes controlar qué tráfico pasa y por dónde va. Los Network Security Groups (NSG) lo permiten o lo bloquean. Las rutas deciden el camino. BGP intercambia rutas de forma dinámica con otras redes.

Network Security Groups (NSG)

Son recursos de Azure con reglas de seguridad de entrada y de salida. Cada regla permite o bloquea tráfico según la IP de origen y de destino, el puerto y el protocolo.

Un NSG es el vigilante que revisa quién puede entrar y salir.

Ejemplo de reglasResultado
HTTPS, puerto 443Permitido
SSH, puerto 22 desde una IP concretaPermitido
El resto del tráficoBloqueado

En los apuntes de Copilot, SSH aparecía permitido desde Internet. Lo corrijo: abrir el 22 a todo el mundo no es buena práctica, así que lo limito a una IP concreta. Es un ejemplo ilustrativo.

Aplicaciones virtuales de red

Son máquinas virtuales especializadas, como un equipo de red reforzado, que realizan una función concreta: un firewall o la optimización de una WAN.

Paquete entrante▼Reglas del NSG▼Aplicación virtual de red▼Máquina virtual de destino

Flujo según el diagrama de Learn.

Enrutar el tráfico

Por defecto, Azure enruta el tráfico entre subredes, redes conectadas, redes locales e Internet. Puedes cambiarlo.

MecanismoQué hace
Tablas de rutasDefinen reglas sobre cómo se dirige el tráfico entre subredes.
Rutas definidas por el usuario (UDR)Te dan más control sobre las tablas de enrutamiento entre subredes o entre redes virtuales.
BGPTrabaja con VPN Gateway, Azure Route Server o ExpressRoute para propagar rutas locales a las redes virtuales de Azure.

BGP

Border Gateway Protocol intercambia rutas de forma dinámica: los routers se avisan entre sí de cómo llegar a otras redes, sin tener que escribir las rutas a mano.

Red local⇄ BGP ⇄Azure

Traducción ASIR

El NSG equivale a las ACL o a las reglas básicas de un firewall. BGP es el protocolo que usan las empresas y los operadores para anunciar rutas. Las tablas y las UDR son rutas estáticas manuales.

Errores frecuentes

ErrorLo que pasa en realidad
Un NSG enruta el tráficoSolo lo permite o lo bloquea. Enrutan las rutas.

Preguntas de comprensión

¿Qué recurso filtra el tráfico entre subredes según IP, puerto y protocolo?

Un Network Security Group.

¿Qué protocolo permite que ExpressRoute intercambie rutas de forma dinámica?

BGP.

TEMA 5/10

VNet Peering

Idea principal. El peering conecta dos redes virtuales directamente. El tráfico entre ellas es privado, viaja por la red troncal de Microsoft y nunca entra en Internet. Las redes pueden estar en regiones distintas, así que puedes crear una red global interconectada.

Es una puerta privada entre dos redes de Azure.

VNet A▼Red troncal de Microsoft▼VNet B

Cuándo usarlo

  • Comunicar redes virtuales entre sí.
  • Compartir aplicaciones entre redes.
  • Conectar regiones.

Traducción ASIR

Es como interconectar dos redes internas con un enlace privado, pero sin montar un túnel VPN entre ellas.

Errores frecuentes

ErrorLo que pasa en realidad
El peering usa InternetUsa la red troncal privada de Microsoft.

Preguntas de comprensión

¿Qué conecta dos redes virtuales directamente y de forma privada?

El VNet Peering.

Una VPN red a red también las conecta, pero con túnel cifrado por Internet.

TEMA 6/10

Azure VPN Gateway

Idea principal. Una VPN usa un túnel cifrado dentro de otra red. Se despliega para conectar redes de confianza a través de una red que no lo es, normalmente Internet. El tráfico viaja cifrado para evitar escuchas. Azure VPN Gateway es la puerta de enlace que lo hace posible.

Un túnel privado que usa Internet como medio de transporte.

Tres tipos de conexión

TipoConectaEjemplo
Punto a sitioUn dispositivo individual con la red virtualUn trabajador remoto desde casa
Sitio a sitioUn centro de datos local con la red virtualUna sede con Azure
Red a redUna red virtual con otra red virtualDos VNets de Azure
Usuario remotoVPN punto a sitioAzure
CPD localVPN sitio a sitioAzure

La línea discontinua es un túnel cifrado a través de Internet.

Cosas que dice Learn sobre el gateway

  • Se despliega en una subred dedicada de la red virtual.
  • Solo puedes tener un VPN Gateway por red virtual, pero uno puede conectar con varias ubicaciones.
  • Todo el tráfico va cifrado dentro del túnel privado. En Azure la autenticación es mediante una clave precompartida.

Basada en rutas o basada en directivas

TipoCómo decide qué cifrar
Basada en directivasIndica de forma estática las IP de los paquetes que se cifran por cada túnel. Evalúa cada paquete contra esas IP.
Basada en rutasEl túnel funciona como una interfaz de red. El enrutamiento IP, estático o dinámico, decide por qué túnel sale cada paquete.
Para el examen. La basada en rutas es la preferida y la más resistente a cambios como crear subredes nuevas. Es obligatoria para conexiones entre redes virtuales, punto a sitio, multisitio o convivencia con un gateway de ExpressRoute.

Traducción ASIR

Equivale a una solución VPN corporativa entre sedes o para teletrabajo, con un concentrador VPN en el extremo de Azure.

Frases de examen

Un empleado se conecta desde casa a la red de Azure. → Punto a sitio.

Conectar el centro de datos de la empresa con Azure por Internet cifrado. → Sitio a sitio.

Errores frecuentes

ErrorLo que pasa en realidad
Sitio a sitio y punto a sitio son igualesUno conecta redes. El otro conecta dispositivos o usuarios.
ExpressRoute es una VPNNo. Es una conexión privada que no pasa por Internet.

Preguntas de comprensión

¿Qué tipo de VPN gateway se recomienda para conectar redes virtuales o para escenarios multisitio?

La basada en rutas.

Es la pregunta 3 de la evaluación de Learn. «Point-based» no existe y la basada en directivas no admite esos escenarios.

TEMA 8/10

Azure ExpressRoute

Idea principal. ExpressRoute extiende tus redes locales a la nube de Microsoft mediante una conexión privada, con la ayuda de un proveedor de conectividad. Esa conexión se llama circuito de ExpressRoute. No pasa por la Internet pública, así que ofrece más fiabilidad, más velocidad, latencias consistentes y más seguridad que una conexión típica.

Red localExpressRoute (privado)ProveedorcircuitoNube de Microsoft

La línea continua es una conexión privada, sin Internet.

Ventajas

  • Conectividad con los servicios de Microsoft en todas las regiones de la zona geopolítica.
  • Conectividad global con ExpressRoute Global Reach.
  • Enrutamiento dinámico con BGP.
  • Redundancia integrada en cada ubicación de emparejamiento. Puedes configurar varios circuitos.

Qué servicios alcanza

  • Microsoft 365 y Dynamics 365.
  • Procesos de Azure, como Virtual Machines.
  • Servicios de nube de Azure, como Cosmos DB y Storage.

ExpressRoute Global Reach

Conecta tus sedes entre sí usando la red global de Microsoft, sin pasar por la Internet pública. Por ejemplo, una oficina en Asia y un centro de datos en Europa, cada una con su circuito.

Sede AExpressRouteRed de MicrosoftExpressRouteSede B

Cuándo elegirla

  • Conectividad privada y consistente entre la red local y Azure.
  • Normativas estrictas o requisitos de transferencia de datos.
  • Latencia predecible y alto rendimiento.
  • No enviar tráfico crítico por Internet.
Matiz de Learn. Aun con ExpressRoute, las consultas DNS, la comprobación de listas de revocación de certificados y las peticiones de Azure CDN siguen yendo por la Internet pública.

Equivale a una línea MPLS o a un enlace dedicado del operador, frente a una VPN que va por la Internet pública.

Ejemplo real: un ayuntamiento conecta su CPD con Azure por ExpressRoute para alojar aplicaciones críticas.

TEMA 9/10

Azure DNS

Idea principal. Azure DNS es un servicio de hospedaje de dominios DNS que resuelve nombres con la infraestructura de Azure. Traduce un nombre como www.empresa.com en una IP. Gestionas los registros con las mismas credenciales, API, herramientas y facturación que el resto de Azure.

Ventajas

VentajaQué significa
Fiabilidad y rendimientoLos dominios se hospedan en la red global de servidores de nombres de Azure. Con anycast responde el servidor más cercano.
SeguridadSe basa en Azure Resource Manager: control de acceso por roles, registros de actividad y bloqueos de recursos.
Facilidad de usoPortal, PowerShell, CLI, API REST y SDK. Sirve para recursos de Azure y externos.
Redes virtuales personalizablesDominios privados con tus propios nombres dentro de las redes virtuales.
Registros de aliasApuntan a un recurso de Azure y se actualizan solos si cambia su IP.

DNS público y DNS privado

CaracterísticaDNS públicoDNS privado
AccesoInternetSolo las redes virtuales vinculadas
UsoWebs públicasServicios internos

Registros de alias

Un conjunto de registros de alias puede apuntar a una IP pública de Azure, a un perfil de Traffic Manager o a un punto de conexión de Azure CDN. Apunta a la instancia del servicio, que a su vez está asociada a una IP, así que si la IP cambia el registro se actualiza solo al resolver.

Importante. No puedes comprar un dominio con Azure DNS. Se compra por una cuota anual con App Service domains o con un registrador externo. Una vez comprado, puedes hospedarlo en Azure DNS para administrar sus registros.

Traducción ASIR

Equivale a un servidor DNS Windows o a BIND, pero hospedado y administrado en Azure. El DNS privado es como la zona interna del dominio de tu empresa.

Ejemplo real: una pyme aloja sus zonas DNS corporativas en Azure DNS.

Arquitectura de ejemplo

Esquema simplificado de los apuntes de Copilot. En la realidad el DNS solo resuelve el nombre. El tráfico de la aplicación no pasa por él.

Errores frecuentes

ErrorLo que pasa en realidad
Azure DNS compra dominiosNo. Administra registros DNS de dominios que ya tienes.
Azure DNS sustituye los controles de seguridad de redNo. Resuelve nombres. El filtrado lo hacen los NSG y demás.

Preguntas de comprensión

¿Cuál es una ventaja principal de Azure DNS?

Administrar los registros DNS con credenciales y herramientas de Azure.

Es la pregunta 4 de la evaluación de Learn. Azure DNS no es un registrador de dominios y no elimina la necesidad de controles de seguridad de red.

Preguntas de repaso

¿Qué es una red virtual de Azure?

La red privada de Azure, donde los recursos se comunican entre sí, con Internet y con la red local.

¿Qué diferencia hay entre un punto de conexión público y uno privado?

El público tiene IP pública y se alcanza desde cualquier lugar. El privado tiene una IP de la red virtual.

¿Qué hace un NSG?

Permite o bloquea tráfico según origen, destino, puerto y protocolo.

¿Por dónde viaja el tráfico de un peering?

Por la red troncal de Microsoft, nunca por la Internet pública.

¿Cuáles son los tres tipos de conexión de VPN Gateway?

Sitio a sitio, punto a sitio y red a red.

¿Qué tipo de VPN gateway se recomienda?

La basada en rutas.

¿Qué configuración tiene un VPN Gateway por defecto?

Activo/en espera: dos instancias, una activa y otra de reserva.

¿Qué es un circuito de ExpressRoute?

La conexión privada entre tu red y la nube de Microsoft a través de un proveedor.

¿Qué hace ExpressRoute Global Reach?

Conecta tus sedes entre sí a través de la red de Microsoft, sin Internet.

¿Qué es un registro de alias?

Un registro que apunta a un recurso de Azure y se actualiza solo si cambia su IP.

¿Puede Azure DNS vender un dominio?

No. Se compra con App Service domains o un registrador y luego se hospeda en Azure DNS.

Escenarios para practicar

Ejercicios propios para entrenar la elección de servicio. No son preguntas de Microsoft.

Una consultora quiere que sus empleados en casa se conecten a las aplicaciones de Azure de forma cifrada.

VPN punto a sitio.

Cada equipo inicia su propio túnel.

Un banco necesita enlazar su CPD con Azure sin pasar por Internet y con latencia predecible.

ExpressRoute.

Una empresa tiene una red virtual en Europa y otra en Asia y quiere que se vean sin salir a Internet.

VNet Peering.

Las redes pueden estar en regiones distintas y el tráfico va por la red troncal.

Quieres que el servidor de base de datos solo sea accesible desde el servidor de aplicaciones.

Subredes y NSG.

Pones la base de datos en su subred y la regla solo admite tráfico de la subred de aplicación.

Una web cambia de IP cuando se reasigna el recurso y no quieres tocar el DNS.

Un registro de alias en Azure DNS.
